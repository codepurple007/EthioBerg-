1. INTRODUCTION
1.1 Purpose
The purpose of this Software Requirements Specification (SRS) document is to provide a detailed description of the BookStore Management System. This system is designed to manage the day-to-day operations of a physical bookstore, including:


Book catalog management


Inventory tracking with real-time updates


In-store sales processing


Customer management


Supplier management


Discount and promotion management


Sales reporting and analytics


User role-based access control


Multi-language support (English, Amharic, Afaan Oromo)


Offline capability for uninterrupted operations


1.2 Scope
The BookStore Management System is a web-based application designed specifically for brick-and-mortar bookstores. It enables:


Customers to browse available books and check stock availability via in-store kiosks or their own devices.


Cashiers to process sales, manage customer registrations, and handle transactions (cash/mobile banking).


Store Admins to manage inventory, create discounts, view reports, and oversee store operations.


Super Admins to manage users, view audit logs, and configure system settings.


Suppliers to view their supplied books, stock levels, and reorder suggestions.


The system integrates with thermal receipt printers and supports offline operations for up to 1 day.

2. OVERALL DESCRIPTION
2.1 User Roles and Characteristics
2.1.1 Customer/Guest
Description: Individuals who visit the store (physically or via the web portal) to browse books.


Capabilities:


Browse and search books


View book details (title, author, genre, price, availability)


Check stock availability


View active discounts/promotions


Switch between languages (English, Amharic, Afaan Oromo)


Registration: Not required for browsing. Customers can be registered by cashiers for purchase tracking.


2.1.2 Cashier/Sales Staff
Description: Store staff responsible for processing in-store sales.


Capabilities:


Search and view books


Create and process sales transactions


Register new customers (optional during checkout)


Process payments (cash/mobile banking with receipt upload)


Print receipts (thermal printer)


View low stock alerts


View their own sales history


Update inventory quantities during checkout (auto-update)


Restrictions: Cannot add/edit/delete books, manage users, or view full reports.


2.1.3 Store Admin/Manager
Description: Store manager responsible for overall store operations.


Capabilities:


All Cashier capabilities


Add/Edit/Delete books (CRUD)


Manage genres (Add/Edit/Delete)


Manage inventory (stock updates, view low stock alerts)


Manage suppliers (contact info, reorder suggestions)


Create/manage discounts (categorical or specific)


View sales reports & analytics (daily, weekly, monthly)


View top-selling and least-selling books


View sales by genre/category


View staff performance metrics


Export reports (PDF, Excel, CSV)


View recent activity logs


Restrictions: Cannot manage users or view full audit logs.


2.1.4 Supplier/Vendor
Description: Book suppliers who provide books to the store.


Capabilities:


View their own contact information (can update phone/email)


View books they supply with current stock levels


View reorder suggestions (auto-calculated)


View purchase order history


Receive notifications for new orders


Restrictions: Limited to their own data only.


2.1.5 Super Admin
Description: System administrator with full system control.


Capabilities:


All Store Admin capabilities


Manage all user accounts (create, edit, delete, assign roles)


View full audit logs (all system activities)


Configure system settings (languages, tax rates, currency, store info)


Manage backup/restore operations


Full access to all data and reports


Restrictions: None.

2.5 Design Constraints
Mobile-First Design: The UI must be fully responsive and work seamlessly on smartphones, tablets, and desktops.


Multi-Language: All UI text must be available in English, Amharic, and Afaan Oromo. Book data must be stored in all 3 languages.


Offline Capability: The system must function fully offline for up to 1 day.


Real-Time Updates: Inventory must update in real-time as sales occur.


No External Dependencies: No dependency on third-party payment gateways or accounting software.


Browser Compatibility: Must work on Chrome, Firefox, Safari, and Edge (latest 2 versions).


2.6 Assumptions and Dependencies
Assumptions
The store has a stable internet connection for normal operations (with offline fallback).


Cashiers have access to a device (desktop/tablet) with a browser for the POS interface.


Thermal receipt printers are ESC/POS compatible.


Customers can access the book catalog via in-store kiosks or personal devices.


Staff have basic computer literacy.


The store has a barcode system? (No - books are searched manually by title/author/ISBN)


Dependencies
Supabase: Requires active subscription for database and storage.


Vercel/Cloud Run: Requires hosting services.


Thermal Printer Drivers: Must be installed on POS devices.


Browser Offline Storage: Must support IndexedDB (modern browsers).


Internet Connection: Required for syncing offline data (when back online).

3.1 Book Management Module
FR-01: Book Catalog Management
Description: The system shall allow Store Admins and Super Admins to manage the book catalog.


Functional Requirements:


FR-01.1: The system shall allow adding a new book with the following fields:


Title (English, Amharic, Afaan Oromo)


Author


ISBN (International Standard Book Number)


Publisher


Publication Year


Genre/Category (multi-select or single)


Description (English, Amharic, Afaan Oromo)


Price (ETB)


Cost Price (ETB)


Quantity (stock)


Reorder Level (minimum stock threshold)


Supplier (select from supplier list)


Book Cover Image (optional)


Language of Book (original language)


Pages


Dimensions (optional)


FR-01.2: The system shall allow editing all book fields.


FR-01.3: The system shall allow soft-deleting books (mark as inactive, not physically removed from database).


FR-01.4: The system shall validate ISBN format (13-digit standard).


FR-01.5: The system shall prevent duplicate ISBN entries.


FR-01.6: The system shall auto-generate a unique Book ID (e.g., B001, B002).


Use Case: Add New Book


Step        Actor        Action
1        Store Admin        Navigates to "Books" → "Add New Book"
2        Store Admin        Fills in all required fields (Title, Author, ISBN, Price, etc.)
3        Store Admin        Selects Genre and Supplier from dropdowns
4        Store Admin        Uploads book cover image (optional)
5        Store Admin        Clicks "Save"
6        System        Validates all fields
7        System        Generates unique Book ID
8        System        Saves book to database
9        System        Displays success message
10        System        Logs action to audit trail

3.2 Inventory Management Module
FR-04: Stock Management
Description: The system shall track and manage book inventory in real-time.


Functional Requirements:


FR-04.1: The system shall maintain current stock quantity for each book.


FR-04.2: The system shall auto-update stock when:


A sale is processed (quantity decreases)


A return/exchange is processed (quantity increases)


A purchase order is received (quantity increases)


An admin manually adjusts stock (with reason)


FR-04.3: The system shall maintain stock adjustment history (who, when, what, why).


FR-04.4: The system shall set a reorder level (minimum stock threshold) for each book.


FR-04.5: The system shall generate alerts when stock falls below reorder level.


FR-04.6: The system shall show "Low Stock" badges on book listings.


FR-04.7: The system shall show "Out of Stock" status when quantity = 0.


FR-04.8: The system shall prevent sales of books with 0 quantity (inventory check during checkout).


Use Case: Process Sale (Inventory Update)


Step        Actor        Action
1        Cashier        Creates a new sale
2        Cashier        Adds books to the sale
3        Cashier        Completes checkout
4        System        Decreases stock for each sold book
5        System        Checks if any book is below reorder level
6        System        Generates low stock alert if needed
7        System        Logs inventory adjustment
FR-05: Stock Alerts & Notifications
Description: The system shall notify relevant users about stock-related events.


Functional Requirements:


FR-05.1: The system shall display low stock alerts on the dashboard for:

FR-05.2: The system shall send email notifications for:

Reorder suggestions (to Store Admin and Supplier)

FR-05.3: The system shall auto-generate reorder suggestions based on:


Current stock levels


Reorder levels

FR-05.4: The system shall allow Store Admin to manually trigger reorder suggestions.


FR-05.5: The system shall display stock alerts in real-time on the dashboard.

Functional Requirements:
